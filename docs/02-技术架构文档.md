# 拾词 · 项目技术架构文档

拾词使用同一套 Vue 前端承载浏览器、手机网页应用（PWA）和 Windows 桌面渲染。应用从固定静态文件读取词库，在客户端完成出题、判题、错词计算与导出。

## 一、技术栈

| 层 | 技术与职责 |
| --- | --- |
| 界面 | Vue 3、TypeScript、CSS、Vite。使用 URL hash 切换首页、词库、筛查、复筛和打印等界面，部署在仓库子路径上。 |
| 词库流水线 | Node.js 24.13 或更高版本运行 TypeScript 导入与验题脚本。固定源数据、SHA-256、排除配置和许可，生成浏览器使用的 JSON。雅思快照提取脚本使用 Python，日常构建读取已保存的快照。 |
| 本地记录 | IndexedDB 保存初筛、复筛及保护性副本。localStorage 记住所选词库和缩放比例。 |
| 移动与离线 | Web App Manifest、Service Worker 和 Cache Storage。前端支持响应式布局，首页提供 iPhone 和安卓安装引导。 |
| 桌面 | Electron 44 系列、electron-builder 26 系列、NSIS。Windows x64 安装程序将 `dist/` 打入应用，Electron 通过本地 `shici://app/` 协议读取。 |
| 输出 | 浏览器 Blob 和文件分享能力输出 JSON、CSV。A4 CSS 配合系统打印界面打印或保存 PDF。 |
| 测试与部署 | Vitest、fake-indexeddb、Playwright。GitHub Actions 运行构建并将 `dist/` 部署到 GitHub Pages。Windows 安装包走 GitHub Releases。 |

## 二、数据与运行流程

```mermaid
flowchart LR
  A["固定词源与许可"] --> B["导入、排除、全量验题"]
  B --> C["三套静态词包"]
  C --> D["Vue 界面与八选一出题"]
  D --> E["初筛与复筛"]
  E --> F["IndexedDB 按词库保存"]
  F --> G["历史错词与待复筛"]
  G --> H["CSV 与 A4 打印"]
  F --> I["JSON 备份与恢复"]
```

| 模块 | 位置与行为 |
| --- | --- |
| 固定词源与产物 | `data/upstream/` 保存源文件、来源与许可，`data/config/` 保存排除配置，`data/reports/` 和 `data/review/` 保存自动报告及人工抽查。构建生成 `public/data/vocabulary.json`、`cet-vocabulary.json` 和 `ielts-vocabulary.json`。 |
| 路由与词库载入 | `src/App.vue` 解析 hash，按选择加载对应词包并做结构检查。主要界面在 `src/components/`。 |
| 出题与判题 | `src/domain/questions.ts` 用原表释义生成正确项和七个干扰项，生成后检查来源和结构。题目内容可重复生成，展示时打乱选项。 `useScreening.ts` 控制作答、保存、反馈和切题。 |
| 复筛 | `review.ts` 按初筛错词和各轮答案推导待复筛集合。开轮时固定该轮词条顺序，刷新后按已有答案恢复。 |
| 备份与输出 | `studyTools.ts` 处理备份读取、校验和恢复，生成带 UTF-8 BOM 的 CSV。 `fileTransfer.ts` 优先使用可用的文件分享能力，失败时可下载。 `PrintSheet.vue` 负责三词一行的打印版式。 |

## 三、存档与升级约束

- IndexedDB 使用 `shici-learning` 数据库与 `sessions` 对象仓库。考研沿用 `initial-screening` 和 `review-history` 等旧键，六级、雅思分别使用 `cet6:`、`ielts:` 前缀。
- 稳定的词条 ID 关联同一词的历次作答。词库内容版本反映固定来源和筛词配置，题目版本及题目签名标识出题数据。保存使用事务与修订号，恢复前保存副本并更新存储代次，防止旧页面覆盖恢复结果。
- 更换词条或干扰项前先留存原题库及测试档案。版本兼容的验收覆盖累计进度、历史作答、当前复筛轮次和旧 JSON。遇到无法识别的版本时保护旧数据。出题改版的兼容回退方案见 [释义去重技术架构](question-quality/02-技术架构文档.md)。
- 网站本地存储随来源地址和浏览器配置独立。桌面应用自己的数据目录与浏览器分开。用户通过同词库的 JSON 备份转移记录。

## 四、生产运行与排障

Web 构建沿用相对资源路径和 GitHub Pages 正式子路径。Service Worker 完成整套预缓存后启用新版，保留旧资源供打开中的旧页面使用。正式入口遇到网络错误时可回退到缓存首页。静态 `404.html` 处理无效路径，反馈信息由用户确认后复制或提交。启动工具 `index.html` 独立提供刷新和修复入口。

发布前执行 `npm ci`、`npm test`、`npm run build`、`npm run test:e2e`。本地用 `npm run dev` 开发，用 `npm run preview` 验证构建。网页从 `main` 触发 [Pages 工作流](../.github/workflows/deploy-pages.yml)。桌面用 `npm run package:win` 构建，安装包先用独立用户目录验收，再提交到发布页。

上线后检查首页和关键 JS/CSS、manifest、Service Worker、三套词包及 404 页面。发现异常先重试并分辨部署、路径和访问环境。题库改版若需要回退，使用已验证能读回新版学习记录的构建。
